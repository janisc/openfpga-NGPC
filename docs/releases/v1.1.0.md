# v1.1.0 — saves that fit, and files that are kept

This release is almost entirely about saves. Before updating, back up
`Saves/ngpc/`: 1.1.0 rewrites saves in a new format that 1.0.x can't read
(see [Going back to 1.0.x](#going-back-to-10x)).

**Big saves now fit.** Thanks to @supergarbo, whose pull request #5 was the
reference for this: the packed save format at the heart of 1.1.0 is their
design, reimplemented on the current code. The Pocket's save slot holds just under 64 KB. Some games save into
a 64 KB flash block, and in 1.0.x those saves did not fit and were cut off
at the slot size. Among the games we found: Biomotor Unitron 2, Faselei!,
Neo Turf Masters, Neo 21, Bust-A-Move and the Ogre Battle Gaiden
translation. How much that cost depends on where a game keeps its data:
Faselei!'s sits early in the block and kept working, while Unitron 2 could
not bring all its save slots back. Saves now use a packed format (V4), so
they fit whole: Unitron 2's 72 KB takes under 4 KB. Saves from 1.0.x load
as before and are rewritten in the new format the next time the game saves;
a 1.0.x save that was already cut off can only give back what it holds.

**A save the core can't use is never overwritten.** Every save now carries
a checksum, and the core checks a file before anything reaches the
cartridge. A file it refuses (damaged, in a format this build doesn't know,
or made with a different dump of the ROM) stays on the card byte for byte,
and the core saves nothing for the rest of that session. 1.0.2 refused such
files too, but then went on saving over them. We reproduced that on
hardware, and it gives the same file as the one attached to #3. That is one
way #3 could have happened; we don't know yet that it did. *(Thank you,
@pomettini, for reporting it and attaching the file: it is what the
reproduction was checked against.)*

**Memories and sleep are safer.** Loading a Memory or waking from sleep
restores the game and its save together or not at all, and a wake that
fails no longer costs the save. Loading a Memory right after the game had
saved no longer hangs, a Memory or sleep state that did not arrive whole is
rejected, and quitting right after loading a Memory can no longer write a
save that mixes the old one with the Memory's.

**Language and Mono Palette apply from the first launch** (#6). The core
used to write them into the BIOS before the Pocket had handed over your
settings, so a game could start in English with Japanese selected. It now
waits for them. Games read these settings when they start, so a change made
while a game runs takes effect at its next launch, as on MiSTer. The
handover timing comes from the Pocket, so if the language still doesn't
follow the setting on yours, please say so in #6.

**`tools/savinfo.py` tells you more:** which build wrote a save, whether its
checksum matches, and which check refused a restore. It now reads sleep
states and Memories (`.sta`) too.

## Found during testing: a launch that doesn't see its save

During our testing, Card Fighters' Clash rarely started without its save.
At launch, the core worked out the wrong checksum for the game itself (not
for the save), so it took the save for another game's. It kept the file
untouched, as above, and the next launch brought the save back. We added
diagnostics and checks but could not pinpoint the cause. It showed up only
on some builds, most likely depending on how the design happens to be laid
out on the FPGA (the fitter's placement and timing), and the release build
never showed it in our testing. On 1.0.2 the same fault could have cost the
save, because 1.0.2 went on saving after refusing a file; it may be another
way #3 could have happened. We can't promise it is gone for good, so here
is what to do if it happens.

## If a game starts without its save

The save is almost certainly still on the card, and 1.1.0 does not
overwrite it. Don't overwrite or delete it yourself:

1. **Quit the core.** Don't play on: nothing in that session is saved.
   To help us find the cause, make a Memory before you quit. Keep it only
   for the report; don't play from it later.
2. *Optional:* copy the save to your computer. It is under `Saves/ngpc/`,
   in the same folders as the game under `Assets/ngpc/` (for example
   `Saves/ngpc/common/<game>.sav`). If you can, open an issue and attach
   it, and the Memory if you made one.
3. **Launch the game again.** If it is the fault described above, the save
   is back.

If it still isn't back, the file is kept, but nothing is saved while it
stays on the card. Before you play again, copy the `.sav` and that game's
Memories off the card (and `System/user_sleepstate.sta`, if you haven't
slept since): each carries a copy of the save. Then see
[Reporting a problem](#reporting-a-problem). To start over instead, move
the file off the card first, and keep it.

## Going back to 1.0.x

**Please don't, without restoring a backup.** 1.0.x can't read the new save
format: given a 1.1.0 save, it refuses it and can then save over it.
Memories made with 1.1.0 carry the new format too. Back up `Saves/ngpc/`
before updating, and if you go back, put that backup back first (progress
made on 1.1.0 stays with 1.1.0).

If you tried a test build: saves from the 1.1.0-rc3 test build are read as
they are; saves from the PR #5 test build (tagged V3) are not read and stay
untouched, so restore your backup or move the file away to start fresh. If
an updater offered you 1.0.2 after a test build, install 1.1.0 instead.

## Known limitations

- **A game may rarely start without its save,** with no message. See above.
- **A Memory that cannot rewind the game's save restarts the game,**
  typically a Memory made before the game first saved, loaded after it has.
  The core leaves the save file alone (unless the game was saving at that
  very moment); continue from the game's own save, or load a more recent
  Memory.
- **A short sound stutter when a Memory loads.** If the game is writing to
  its save at that moment, the load waits for the flash write to finish.
  That wait is deliberate.
- **Menu Reset unloads the cartridge** and lands in the BIOS menu (MiSTer's
  keeps the game). To restart a game, relaunch it. The save is kept.
- **The clock after sleep:** after a wake or a Memory load, the NGP's clock
  is behind by the time in between, until you relaunch or use Reset to BIOS.
- **Mono Palette has no effect with System = Mono:** the mono BIOS has no
  palettes.
- **Neo Turf Masters' in-game suspend** does not offer resume. Use sleep to
  pause mid-round.

Details for each are in
[docs/KNOWN_BEHAVIORS.md](https://github.com/janisc/openfpga-NGPC/blob/main/docs/KNOWN_BEHAVIORS.md).

## Reporting a problem

Please open an issue with the game, what happened just before (sleep, a
Memory, Reset, a relaunch), your Pocket firmware version, and the `.sav`
(and the output of `python3 tools/savinfo.py "<the .sav>"` if you can). If a
wake or a Memory load went wrong, a Memory made straight after it helps: it
records how that load ended.

Saves and Memories from 1.0.x still load. Built with Quartus Prime Lite 25.1.
