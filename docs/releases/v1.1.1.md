# v1.1.1 — the PSRAM, set up at every start

**Fixed: a save could be damaged when the PSRAM had been left with
non-default settings.** While a game runs, the core keeps a working copy of
its save in the Pocket's PSRAM. That copy goes into sleep states, Memories
and, when you quit, the save file. The PSRAM has settings registers of its
own, including how much of the chip it keeps refreshed, and they keep their
values until the Pocket is switched off, also from one core to the next.
1.1.0 and earlier relied on the chip's power-on settings and never wrote
them. If the PSRAM had been left with its refresh switched off, the working
copy could lose bits within minutes of play, and quitting then wrote the
damaged copy to the card. We reproduced this on hardware.

1.1.1 sets the PSRAM up itself every time it starts: full refresh and the
standard asynchronous mode on both halves of the chip, read back to make
sure they took. This should prevent the damage whatever state the chip was
left in.

A save damaged this way is refused at the next launch and stays on the card
as it is, but its contents are lost. If you have a backup of `Saves/ngpc/`,
put the file back from it.

**`tools/savinfo.py` shows the PSRAM's state.** Every save 1.1.1 writes, and
every sleep state and Memory, records how the core found the PSRAM when it
started and whether its set-up read back as written. If a save problem is
reported, this shows at once whether the PSRAM was involved.

**Start-up waits for both memories.** The core now tells the Pocket it has
booted only once the cartridge memory (SDRAM) has finished its start-up and
the PSRAM is set up, about 0.2 ms later than before. This closes a gap that
has not been seen to cause a problem, but that nothing prevented.

Saves and Memories work in both directions between 1.1.0 and 1.1.1.

## If a game starts without its save

The guidance from 1.1.0 still applies: quit the core and launch the game
again; the save file is kept. See
[docs/KNOWN_BEHAVIORS.md](https://github.com/janisc/openfpga-NGPC/blob/main/docs/KNOWN_BEHAVIORS.md).

## Reporting a problem

Please open an issue with the game, what happened just before (sleep, a
Memory, Reset, a relaunch, other cores played since the Pocket was switched
on), your Pocket firmware version, and the `.sav` (and the output of
`python3 tools/savinfo.py "<the .sav>"` if you can).

Built with Quartus Prime Lite 25.1.
